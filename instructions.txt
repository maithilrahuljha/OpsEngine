--------------------------------------------------------------------------------
  WHAT THIS APP DOES (so you know what you are deploying)
--------------------------------------------------------------------------------
Paramount OpsEngine is the internal operations platform for the institute.
It has SEVEN sections in the left-hand menu:

   📊  Command Center        — live dashboard (cadet count, occupancy, revenue,
                               admissions funnel, CBT ranks)
   📈  Admissions CRM        — SALES TEAM tool: track every enquiry from first
                               call to final enrolment (NEW here — see below)
   🎖️  Cadet Directory       — full list of enrolled cadets
   🏢  Hostel & Discipline   — beds, nightly roll-call, incident register
   🩺  Medical Pre-Screen    — 6/6 vision & colour-blindness checks
   ⚓  Sponsorship Vivas     — mock interview scoring for shipping companies
   📝  CBT Examination Hub   — mock test results and All-India Ranks

There are SIX types of login (called "roles"). Each role can see and do
different things:

   • Director General   — sees everything, can change nothing (read-only)
   • COO                — full control of cadets, hostels, medical, and CRM
   • Campus Manager     — same as COO for their campus
   • Academic Lead      — manages CBT exams and sponsorship vivas
   • Chief Warden       — manages attendance and discipline
   • Sales Executive    — manages the Admissions CRM sales pipeline (NEW)


--------------------------------------------------------------------------------
  WHAT'S NEW: THE ADMISSIONS CRM (for the Sales Team)
--------------------------------------------------------------------------------
The CRM ("Customer Relationship Management") is where your admissions/sales
counsellors manage prospective students. Think of it as the sales funnel:

   NEW → CONTACTED → QUALIFIED → COUNSELING → APPLICATION → ADMITTED →
   ENROLLED (won)      ... or ... LOST (didn't join)

For each lead (prospective student) the CRM stores:
   - Name, phone, email, city
   - Where the enquiry came from (Website, Referral, Walk-in, Education Fair…)
   - Which course/batch they want
   - Which counsellor owns the lead
   - Estimated course fee (so you can see total pipeline value in ₹)
   - A "lead score" (0–100) showing how hot the prospect is
   - A follow-up date
   - A full timeline of every call, email, WhatsApp, meeting, and site visit

When a lead finally joins, the counsellor clicks "Convert to Cadet" and the
system automatically creates a cadet record with a fresh roll number — no
double data entry.

================================================================================

       c. Repository name:  paramount-opsengine
       d. Choose "Private" (only you can see it).
       e. Do NOT tick "Add a README" or any checkbox.
       f. Click the green "Create repository".

  PART 3 — CREATE THE DATABASE ON NEON
================================================================================

  3.1  Create the database project
       a. Sign in at  https://neon.tech.
       b. Click "Create Project" (or "New Project").
       c. Fill in:
              Project name:      paramount-opsengine
              Database name:     app_db
              Region:            pick the one nearest India, e.g.
                                 "Asia Pacific (Singapore)" or
                                 "Europe (Frankfurt)"
              Postgres version:  leave default
       d. Click "Create Project".

  3.2  Copy the connection string (this is your database's address+password)
       a. After creation, Neon shows a box called "Connection string".
       b. Turn ON "Connection pooling" (or pick the option that says
          "Pooled connection"). This is important so the website doesn't run
          out of connections.
       c. Click the copy icon. The string looks like this (yours will differ):

              postgresql://neondb_owner:AbC123xyz@ep-cool-name-12345-pooler.
              ap-southeast-1.aws.neon.tech/app_db?sslmode=require

       d. Paste it into Notepad/TextEdit and save it. Label it
          "DATABASE_URL". You will use it TWICE — in Part 4 and Part 5.

  🔒 Treat this string like a password. Never post it publicly.

  ✅ Your database exists (but it is empty — Part 5 fills it).


================================================================================
  PART 4 — DEPLOY THE APP ON VERCEL
================================================================================

  4.1  Import your GitHub code into Vercel
       a. Sign in at  https://vercel.com.
       b. Click "Add New..." → "Project".
       c. You'll see your GitHub repositories. Find "paramount-opsengine"
          and click "Import".
       d. If it's not listed: click "Adjust GitHub App Permissions", give
          Vercel access to the repository, then return.

  4.2  Set up the project (BEFORE clicking Deploy)
       On the "Configure Project" screen:
       a. Framework Preset: should auto-show "Next.js" — leave it.
       b. Root Directory: leave as  ./
       c. Build settings: leave all defaults.
       d. Open the "Environment Variables" section and add TWO entries.
          For each: type the Name, paste the Value, click "Add".

          ENTRY 1
             Name:   DATABASE_URL
             Value:  (paste the Neon pooled string from Part 3.2)

          ENTRY 2
             Name:   AUTH_SECRET
             Value:  any long random secret text. Easy way to make one:
                       • go to  https://www.uuidgenerator.net/
                       • copy the UUID shown
                       • paste it in twice, back to back, so it's extra long
                     Example (MAKE YOUR OWN — do not copy this one):
                       6b1e9c2a-...-a7f3   6b1e9c2a-...-a7f3

  4.3  Deploy
       a. Click the big "Deploy" button.
       b. Wait 2–4 minutes while it builds. You'll see a log scrolling.
       c. When done you'll see confetti 🎉. Click "Continue to Dashboard".
       d. At the top, note the temporary web address, e.g.
              https://paramount-opsengine-xxxx.vercel.app

  ⚠ If you open it and log in NOW, it will FAIL — the database has no tables
     yet. That is expected. Part 5 fixes it.

  ✅ The app is deployed. It just needs its database set up.

================================================================================
  PART 6 — CONNECT YOUR GODADDY DOMAIN
================================================================================

Goal: make the site open at  https://paramountmerchantnavy.com  instead of
the long …vercel.app address.

  6.1  Tell Vercel about your domain
       a. In Vercel, open your project → click the "Settings" tab (top).
       b. In the left menu, click "Domains".
       c. In the box, type:   paramountmerchantnavy.com   → click "Add".
       d. Choose the recommended option:
              "Redirect www.paramountmerchantnavy.com →
               paramountmerchantnavy.com"
          → click "Add".
       e. Vercel now shows "Invalid Configuration" and lists the DNS records
          you must create at GoDaddy. They look like this (use YOUR values):

              Type   Name   Value
              ────   ────   ─────────────────────
              A      @      76.76.21.21
              CNAME  www    cname.vercel-dns.com

          Keep this Vercel tab OPEN — you'll copy from it.

  6.2  Open the DNS settings at GoDaddy
       a. In a new tab, sign in at  https://godaddy.com.
       b. Top-right: your name → "My Products".
       c. Find  paramountmerchantnavy.com → click the "..." → "Manage DNS"
          (or click the domain, then "DNS").

  6.3  Remove GoDaddy's default "parking" records
       a. In the records table, find and DELETE:
              • the  A  record with Name  @  (points to a GoDaddy IP)
              • the  CNAME  record with Name  www
         (Click the pencil/edit icon → Delete/Remove → confirm.)
       b. DO NOT touch records of type  NS  or  SOA.
       c. DO NOT touch any  MX  records (those run your email).

  6.4  Add Vercel's two records
       RECORD 1 (the main domain):
              Type:  A
              Name:  @
              Value: 76.76.21.21     ← use EXACTLY what Vercel showed you
              TTL:   1 Hour (or default)
          → Save.

       RECORD 2 (the www version):
              Type:  CNAME
              Name:  www
              Value: cname.vercel-dns.com   ← use EXACTLY what Vercel showed
              TTL:   1 Hour (or default)
          → Save.

  6.5  Wait, then confirm
       a. DNS changes spread across the internet in anywhere from 5 minutes
          to a few hours (occasionally up to 48h).
       b. Go back to the Vercel "Domains" page and refresh every few minutes.
          The status changes:  Invalid → Valid Configuration → Certificate
          Issued (green tick ✓).
       c. You can also check progress at  https://dnschecker.org  (enter
          paramountmerchantnavy.com, type A — you want to see 76.76.21.21).

  ✅ Once Vercel shows green ticks for both the domain and the www version,
     you're live.

================================================================================
  PART 8 — IMPORTANT: SECURE THE APP BEFORE REAL USE
================================================================================

The demo accounts all share the password  paramount123. Before real staff
and real cadet/lead data go in, you MUST change these.

  8.1  Simple approach (ask a developer for 15 minutes)
       Have a developer:
         • Edit  scripts/seed.ts  to set real names and strong passwords for
           each role (including the Sales Executive), OR
         • Add new staff rows directly, using the password-hashing method in
           src/lib/auth.ts (passwords are stored as secure SHA-256 hashes,
           never as plain text).

  8.2  If you do it yourself via Neon
       Passwords are NOT stored as plain text, so you cannot just type a new
       one into the table. You need the hashed value. The safest path is to
       re-run the seed with new passwords (developer task). Do not skip this
       step for a production system.

  8.3  Keep your secrets safe
       • Never share the Neon DATABASE_URL or the Vercel AUTH_SECRET.
       • Never commit a real  .env  file to GitHub.

================================================================================
  PART 10 — TROUBLESHOOTING
================================================================================

  "This site can't be reached" at paramountmerchantnavy.com
     → DNS hasn't spread yet. Wait 30 min and retry.
     → Confirm you deleted GoDaddy's old parking A and CNAME records (6.3).
     → Check status at  https://dnschecker.org.

  Login says "Invalid credentials"
     → Password is exactly  paramount123  (all lowercase, case-sensitive).
     → Confirm you ran the seed (Part 5). The  users  table should have
       6 rows (including sales@paramount.in).

  Login works but a page shows "Something went wrong"
     → DATABASE_URL in Vercel is wrong/missing. Vercel → Settings →
       Environment Variables → fix it → then Deployments tab → "Redeploy".

  The CRM (or another page) is empty when it shouldn't be
     → The seed didn't load that table. Re-run  npx tsx scripts/seed.ts
       from your computer (Part 5). If it says "already seeded — skipping",
       the data is actually there; just refresh the page.

  "Too many database connections"
     → Your DATABASE_URL must be the POOLED string (has  -pooler  in the
       address). Copy the pooled version from Neon and update it in Vercel,
       then redeploy.

  "SSL certificate error" right after connecting the domain
     → Vercel needs 5–10 min to issue the certificate after DNS goes valid.
       Wait and reload.

  Changes pushed to GitHub aren't showing on the live site
     → Vercel → Deployments tab. If the newest build has a red ✗, click it
       to read the error. If it's green ✓, hard-refresh your browser
       (Ctrl+Shift+R / Cmd+Shift+R).

  "Convert to Cadet" fails saying email already exists
     → A cadet with that email is already enrolled. Edit the lead's email or
       remove the duplicate cadet, then convert again.
